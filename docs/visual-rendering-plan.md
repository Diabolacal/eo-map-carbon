# Visual rendering lab — plan

Research checkpoint after parallel read-only investigation of EO-Map
(`C:\dev\eo-map`), public Trinity (`C:\dev\carbon-upstream\trinity`), and this
host. Implementation follows this document. Aesthetics are **not** proven here;
this is a tunability milestone.

## Chosen star rendering path

**TrinityAL two-stream instanced camera-facing quads.**

- Stream 0: unit quad corners (`float2`, 4 vertices).
- Stream 1: per-star `{position, aSize, rgb, emissive}` (5,485 instances).
- Index buffer: 6 indices, two triangles (`0,1,2, 1,2,3`).
- Draw: `SetTopology(TOP_TRIANGLES)` then
  `DrawIndexedInstanced(4, 0, 2, 5485)` — the 4-arg TrinityAL overload used by
  `trinityal/tests/Rendering.cpp` `CanDoInstancedRendering`.
- Vertex shader expands corners along host-computed view right/up, with a
  screen-pixel clamp (min/max) so zoom does not explode or vanish the discs.
- Pixel shader: soft radial falloff (`1 - saturate(length(corner))`, squared).
  No textures, no EVE client assets.
- Blend: Eve-style additive (`BM_ONE` / `BM_ONE`), depth test on, depth write
  off, no cull — from `Tr2EffectStateManager` `RM_ALPHA_ADDITIVE`.
- One star draw call. Keep the proven `TOP_POINTS` path as `--points` / F7
  diagnostic fallback.

## Chosen bloom path

**TrinityAL-native HDR extract → separable blur → composite.**

`Tr2PPBloomEffect` / `Tr2PostProcessRenderer` are **not** usable from this host.
They require Blue, `Tr2Effect`, `res:/Graphics/Effect/...` FX files that are not
in the public tree, `EveSpaceScene`, and `Tr2GpuResourcePool`.

Verified TrinityAL pieces instead:

- Scene is drawn to an offscreen `PIXEL_FORMAT_R16G16B16A16_FLOAT` texture
  (`RENDER_TARGET | SHADER_RESOURCE`). The swap-chain backbuffer is not
  sampleable (`SWAP_EFFECT_DISCARD`).
- Fullscreen clip-space quad + `DrawPrimitive(0, 2)`, pattern from
  `CanRenderToRenderTarget`.
- Sample via `Tr2ResourceSetDescriptionAL::SetSrv` / `SetSampler` +
  `SetResourceSet`. Resource sets are immutable after `Create`; one set per
  (program, source texture).
- `Clear` after `SetRenderTarget` clears the bound RT (not only the swap chain).
- Empty `Tr2ResourceSetAL` does **not** unbind SRVs. Bind a 1×1 dummy set
  before drawing the scene so `sceneRT` is not still a PS SRV.

Passes (bloom ON): extract at ½ res → Gaussian H → Gaussian V → composite
`scene + bloom * strength` with mild Reinhard and exposure.

Bloom OFF: skip extract/blur; blit `sceneRT` through the same composite shader
with strength 0.

## EO-Map data fields and visual rules

Default EO-Map look is **temperature blackbody**, not security colour.
`starColoringMode` defaults to `'off'`. Security is an optional overlay only.

| Source field | Visual | Notes |
| --- | --- | --- |
| Contract A `systems.star_temperature` (kelvin) | RGB | Harvard D65 stops, T clamped `[2300, 40000]`. `starColors.ts` `getStellarTemperatureColor`. |
| same temperature | Emissive 1×–6× | `1 + 5 * log10-lerp(T, 2300, 7496)^3`. Hottest pinned k-space star is 7496 K. |

| camera distance + zoom | Depth dim | `dynNear/Far = (3, 275) * max(0.1, camDist / 165)`. |
| *(none)* | Gate colour | `#444444`, brightness 1.8–2.4, opacity 0.60, `uBoostGate` 2.0. |
| prefs | Bloom | UnrealBloom strength 0.25, threshold 0.25, radius 0; exposure 1.1. |

## Data-export changes

Keep `NEDEN1B` / `NEGATE1` frozen. Add a sidecar:

`data/new_eden_star_visuals.bin` (`NESTAR1`)

- Records: `system_id`, `temperature_k`, `spectral_letter` (first char of
  `star_class`), pad.
- Same 5,485 ids, same order as `new_eden_systems.bin`.
- Raw metadata only. Colour, emissive, and size are computed at runtime so
  sliders can retune presentation.
- Regenerated by `scripts/export-new-eden-systems.py` from the pinned Contract A
  DB. No SQLite / ESI / EO-Map process in the executable.

## Attenuation approach

View-space Z (`clip.w` for this RH `PerspectiveFovRH`), not Euclidean, not NDC z.

Zoom-scaled window (EO-Map spirit):

```
scale = max(0.1, cameraDistance / 165)
dynNear = 3 * scale
dynFar  = 275 * scale
t = saturate((viewZ - dynNear) / (dynFar - dynNear))
starGain = lerp(nearStarAtten, farStarAtten, t)
gateGain = lerp(1, 1 - 0.65 * gateDistanceAtten, t)
```

Gates stay `TOP_LINES` (1 px). Fade is intensity/alpha only. Variable-width
camera-facing ribbons are a later option, not this milestone. DX11 has no
line-width API; `RS_ANTIALIASEDLINEENABLE` is not applied.

Sub-pixel coverage: if unclamped star pixels &lt; `minPx`, multiply colour by
`unclamped / minPx` so the min-size floor does not blow out the far field.

## Debug tuning approach

Separate modeless Win32 tool window (owner = DX HWND), Common Controls
trackbars, `comctl32` only. No ImGui. Not created in `--smoke`.

`TuneParams` live on the host; sliders write the struct; the frame loop reads
it into constant buffers. Reset button / F9. Dump button / F8 writes
`eo-map-carbon-neweden-tune.ini` next to the exe, logs the text, and copies to
the clipboard when possible. The INI is **not** loaded on startup.

## Expected draw / pass architecture

```
HDR sceneRT (RGBA16F) + D24S8
  1. TOP_LINES gates (alpha blend, Z write on)
  2. instanced star quads (additive, Z write off)
     optional: TOP_POINTS diagnostic instead of (2)
bloom ON:
  3. extract 1/2
  4. blur H 1/2
  5. blur V 1/2
  6. composite to backbuffer
bloom OFF:
  3. blit/tonemap sceneRT to backbuffer
```

| Mode | Draw calls | PP passes |
| --- | --- | --- |
| sprites + bloom | 6 | 4 (extract, H, V, composite) |
| sprites, bloom off | 3 | 1 (tonemap blit) |
| `--points` + bloom | 6 | 4 |
| `--points`, bloom off | 3 | 1 |

## Important Carbon limitations

- `EveSpriteSet` / `Tr2QuadRenderer` / `EveStarfield` / `Tr2PPBloomEffect` are
  full-Trinity + Blue. Architectural reference only.
- No sprite/star HLSL in the public Trinity tree. Host HLSL via fxc/bin2h.
- `RS_POINTSIZE` is ignored on DX11 (1 px). Sized stars **must** be quads.
- No TrinityAL camera, billboard helper, or `SetShaderConstant`.
- Resource sets do not update in place; recreate on resize with the RTs.
- `CreateBackBuffers` resets viewport and unbinds depth.
- Constant-buffer `Create` size must be a multiple of 16 (TrinityAL does not pad).
- This host remains DX11-only.
